# Audit: the Filum engine before its public release

**Date:** 2026-10-27
**Object:** this repository at commit `e10744e` (`87ee7d0` plus one test-only commit). 52 commits since the baseline, 184
files (+4,742 / −2,022).
**Baseline:** the previous independent audit of 2026-10-18 on `929c958` (overall 7.0, then 7.5 after the fact-ledger fixes
`2c3c6d2`..`df278ec`); it was kept with the development notes.
**Versions:** written before the first public release was numbered 1.0.0; "2.0.0" below is that release.
**Auditor:** independent and read-only; wrote none of the code or the specs. The fixes made after this audit are listed at
the end.

## Summary

- **Verdict: 7.5/10, unchanged.** The release is held up by documentation and claims, not by code: about one day of fixes
  plus the release-day actions.
- **Better:** hooks give "knows you from the first message" (`brief`, `log`, `tidy`); rules and open items are facts; a
  secret filter on every write; planned values; a pre-registered personal benchmark (knows-you) with its frozen data in
  the tree; an isolated Claude Code harness and a second model family; 596 tests green (544 before).
- **Did not move:** the recall code (`EventTools.cs`, `RecallPage.cs`, `ToolTraits.cs`, `JsonLines.cs`, `Downloads.cs`,
  `AtomicFile.cs` are byte-identical to `929c958`): all five recall items and the MCP-hygiene items of the baseline's
  "can come after" are still open.
- **Blockers:** README and CHANGELOG describe the wrong core tool set; the evaluation text contradicts itself and
  overstates what was pre-registered; unfinished text (CI "paused", `CLAUDE.md` "Version 1.x"); the release is not tagged.
- **New defects:** two in planned values (reproduced by a test) and a design risk: rule facts are a persistent
  instruction channel.

### 1.1 Fact model (7.5 → 7.5)

- **Improved (verified):** rules and open items hold many values; `fact_end` ends one by its `value` and keeps the events
  that ended it (`FactService.cs:243-278`, `FactTools.cs:45-49`). The baseline's two minor cases are fixed (`8c32893`;
  `MemoryServiceContract.LedgerDays.cs:91,104`). Planned values: "now" is the engine clock's day (`FactService.cs:84-91`,
  `FactService.Planned.cs:10-25`, `Fact.HeldOn`).
- **New defects (verified by probe tests):**
  - Restating the current value while a planned one exists is not idempotent: it writes a revision that splits the
    current row (`AlreadyAsync` tests `f.IsOpen`, `FactService.cs:140`, but a value with a planned successor is closed).
  - A fact with a planned change cannot be ended: `fact_end` with no day is refused ("holds since a later day"),
    because `End` sees only open rows (`:254-265`).
  - Other `IsOpen` callers still mean "current" (aliases, `FactTable.cs:107`); inferred low impact.
- **Still missing:** an as-of query over `recorded_at`; entity resolution beyond aliases; the whole-CSV rewrite on every
  write; "today" is the UTC day (`McpClock.cs:41-42`).

### 1.2 Extraction and writing (7.0 → 7.5)

- **Improved (verified):** every message logged by code before the model reads it (`HookLog.cs:41-56`), never blocking
  it; the Stop hook asks for `memory_consolidate` once per session over 10 waiting messages (`HookTidy.cs:96-108`);
  `memory_consolidate` in the core profile; a secret filter on events, imports and file writes; new instruction parts
  (`Durable`, `WithoutAsking`, `Unknown`, `RuleReach`); a cross-process lock lets the hooks and the server share a folder.
- **Weak:** capture still depends on the host model (gpt-4o-mini without hooks is "not supported" by the README); the
  secret filter knows English labels and known prefixes only; redaction runs on the whole content of every write, so an
  edit can change unrelated text that looks like `password: …` (inferred).

### 1.3 Retrieval (6.0 → 6.0)

- `events_search` is unchanged since the baseline (§2). New: `FactRecall` matches planned values; the per-message recall
  gives at most 3 event hits of 200 characters, plus matched facts and the rules.
- **Weak:** the hooks open the engine without the embedding model, so hook recall is word-only (inferred, low).
  Measured: LongMemEval_S, 50 questions, Filum 41 against BM25 44: on par, no gain.

### 1.4 MCP interface (7.5 → 7.5)

- **Improved:** the three hooks with documented output; the rules the person set appended to the server instructions
  within the room under 4,095 characters, read once at start; 14 tools in the smoke.
- **Still wrong (verified):** `memory_write` is non-destructive (`ToolTraits.cs:35`); the snapshot pins only name,
  description and parameters; `events_search`'s description and `ReadWhole` are stale (`EventTools.cs:22`,
  `InstructionParts.cs:32`); the `"Refused: "` prefix and its substring detection in the harness remain; no `--help` or
  `--version`, and any unknown argument starts a server on `~/.filum`.
- **New:** every session asks for a consolidation pass after the first request, on top of the Stop hook; the README does
  not say so.

### 1.5 Evaluation (7.5 → 7.5)

- **Improved (verified):** knows-you's four synthetic people, each committed before any run on it, with thresholds in
  spec 050; the isolated harness, checked before the first session; a second model family; spec 056's "not met" reported
  honestly.
- **Down (verified):**
  - `evals/bench/README.md` still says the README's numbers were not made with this harness; the README now says the
    opposite.
  - The README says "Haiku 4.5 meets the pre-registered thresholds", but the thresholds registered then were spec 050's,
    set against a gpt-4o-mini baseline and with a "loses no probe" clause the README drops; Haiku thresholds were first
    written in spec 055, for person 4 only; gpt-4o-mini, the registered model, misses them.
  - "Person 3, the only one the engine never saw" is stale: specs 055 and 056 used the failures on people 1-3.
  - Person 4, the held-out person of the current engine, is not in the README (22/23 with hooks).
  - No number names its engine commit; per-question results are not published; 23 probes per person, one repetition.

### 1.6 Engineering quality (8.0 → 7.5)

- **Good:** 0 warnings, 596 .NET and 26 Python tests; single-file publish and the smoke work; the release workflow scans,
  builds, tests, publishes four RIDs with `SHA256SUMS` and smoke-tests; `e10744e` fixed the test fixtures the secret scan
  flagged, which would have failed the release workflow at `87ee7d0`.
- **Down:** CI paused (`CONTRIBUTING.md`), so no Linux or macOS run was seen, and the release workflow may not run
  either; the CHANGELOG contradicts itself (§2); `CLAUDE.md` says "Version 1.x"; the eval isolation copies the Claude Code
  login to temp and deletes it only on process exit (dev-only, low); no telemetry; `JsonLines` drops unreadable lines
  silently.
